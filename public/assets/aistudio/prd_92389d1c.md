## 1. Ringkasan

MetaScope adalah penampil metadata yang bisa membongkar sebuah file sampai ke lapisan byte dan menampilkan semua yang ada di dalamnya: tag EXIF/XMP/IPTC, struktur kontainer, bitstream, timestamp, lokasi, provenance (C2PA), jejak software, serta sinyal privasi. Tidak seperti viewer metadata biasa yang hanya mencetak daftar tag, MetaScope:

1. **Membedah berlapis** (file, kontainer, stream, struktur box/chunk, bitstream, statistik) dan menunjukkan data yang tidak muncul di alat umum, misalnya tanda tangan encoder di dalam bitstream video.
2. **Menyilangkan hasil** antar lapisan (cross-check) sehingga pengguna tahu apakah file utuh, dipotong, atau diubah.
3. **Memisahkan fakta dari tebakan.** Setiap kesimpulan diberi label keyakinan (`pasti`, `kuat`, `heuristik`).
4. **Menjaga privasi secara default.** Analisis berjalan di browser; file tidak diunggah kecuali pengguna memilih mode analisis mendalam.
5. **Menjelaskan hasil dengan bahasa awam** lewat AI (Gemini), dengan batas ketat: AI hanya menjelaskan hasil parser, tidak pernah menjadi parser.

Dasar rancangan: analisis nyata terhadap sebuah video MP4 (HEVC + AAC) yang menghasilkan temuan berlapis (lihat Lampiran A) dan prototipe `vidmeta.py` yang sudah diuji pada file itu.

## 2. Latar belakang dan masalah

Viewer metadata online yang ada (misalnya metadataview.com) umumnya membungkus satu atau dua alat (ExifTool, ffprobe) dan menampilkan hasilnya per kelompok tag. Hasil analisis manual pada satu video menunjukkan celah yang jelas:

| Celah pada viewer biasa | Bukti dari analisis video contoh | Kebutuhan produk |
| --- | --- | --- |
| Tidak membaca isi bitstream | Encoder `ByteVC1-v1.10.0.4` hanya ada di SEI di dalam sampel video | Parser bitstream (HEVC/H.264) |
| Tidak menyilangkan data | Jumlah sampel, keyframe, paket audio, dan total ukuran box baru bisa dipercaya setelah dicocokkan | Mesin cross-check |
| Tidak menguji hash di tag | `vid_md5` di tag tidak cocok dengan bagian mana pun dari file | Uji hash tag terhadap region file |
| Tidak membedakan fakta dan tebakan | Waktu posting dari ID video hanyalah heuristik | Label keyakinan |
| Tidak menunjukkan bagian file yang tak terjelaskan | Hanya 0,66% file adalah non-media; sisanya perlu dipetakan | Peta cakupan byte |
| Upload ke server pihak ketiga | File sensitif meninggalkan perangkat | Mode privat di browser |

## 3. Tujuan, non-tujuan, dan metrik

### 3.1 Tujuan

1. Menampilkan **semua metadata yang benar-benar ada** pada file dari keluarga format utama (gambar, video, audio, dokumen, arsip) beserta struktur internalnya.
2. Memberi **penilaian yang bisa dipertanggungjawabkan**: cross-check, label keyakinan, dan peta cakupan byte.
3. Menjadi **alat privasi**: skor risiko, temuan berseverity, dan saran tindakan.
4. **Tanpa unggah secara default.**
5. Bisa dibangun dan diiterasi lewat Google AI Studio Build, lalu dipindahkan ke repositori sendiri.

### 3.2 Non-tujuan (versi 1.0)

- Bukan alat forensik tingkat pengadilan; laporan tidak diklaim sebagai bukti hukum.
- Tidak melakukan identifikasi orang (pengenalan wajah, penelusuran identitas akun, reverse image search).
- Tidak menyimpan file pengguna secara permanen dan tidak menyediakan tautan laporan publik.
- Tidak memulihkan piksel atau konten yang sudah dihapus (metadata hanya mendeskripsikan file).
- Tidak mengedit metadata kecuali modul pembersih opsional (FR-22).

### 3.3 Metrik keberhasilan (target usulan, perlu divalidasi)

| Metrik | Target usulan |
| --- | --- |
| Cakupan format utama (gambar, video, audio, dokumen) yang terbaca tanpa error pada korpus uji | ≥ 98% |
| Kesesuaian dengan ExifTool/MediaInfo pada korpus uji (selisih tak terjelaskan) | ≤ 1% field |
| Parser crash pada fuzzing | 0 |
| Waktu laporan ringkasan untuk file ≤ 50 MB di laptop umum | ≤ 3 detik |
| File yang meninggalkan perangkat pada mode default | 0 |
| Pengguna yang memahami temuan utama tanpa membuka tab teknis (uji pengguna) | ≥ 80% |

## 4. Persona dan skenario

| Persona | Kebutuhan | Skenario utama |
| --- | --- | --- |
| Pengguna umum yang peduli privasi | Tahu apa yang bocor sebelum membagikan foto atau video | Unggah foto, lihat skor risiko dan GPS, lalu bersihkan |
| Jurnalis atau pemeriksa fakta | Menilai asal-usul dan kemungkinan manipulasi | Buka video, baca rantai pemrosesan, C2PA, dan anomali timestamp |
| Pembuat konten | Memverifikasi hasil ekspor (codec, bitrate, warna) | Periksa video sebelum diunggah ke platform |
| Pengembang atau analis | Bedah teknis sampai byte | Jelajahi pohon box, hex, bitstream, ekspor JSON |
| Tim HR/legal/kantor | Memeriksa dokumen sebelum dikirim | Buka DOCX/PDF, lihat penulis, revisi, komentar tersembunyi |

User stories inti:

- Sebagai pengguna, saya ingin menjatuhkan file dan langsung melihat ringkasan temuan terpenting tanpa membaca ratusan tag.
- Sebagai pengguna, saya ingin tahu apakah file saya mengandung lokasi, nama, atau perangkat saya.
- Sebagai analis, saya ingin menelusuri dari satu temuan ke byte aslinya (offset dan hex).
- Sebagai pemeriksa fakta, saya ingin tahu mana temuan yang pasti dan mana yang tebakan.
- Sebagai pengguna, saya ingin membandingkan file sebelum dan sesudah dibersihkan.

## 5. Cakupan format ("melihat semua")

"Semua" didefinisikan sebagai: **semua yang terdokumentasi dan ada di dalam file**, ditambah peta byte yang menunjukkan bagian mana yang belum terjelaskan. Produk tidak boleh mengklaim melihat data yang tidak ada, terenkripsi, atau sudah dibuang.

| Keluarga | Format (v1.0) | Metadata dan struktur yang dibaca | Mesin |
| --- | --- | --- | --- |
| Gambar | JPEG, PNG, WebP, GIF, TIFF, HEIC/HEIF, AVIF, BMP, SVG; RAW umum (DNG, CR2/CR3, NEF, ARW) | EXIF, GPS, IPTC, XMP, ICC, MakerNote, thumbnail tertanam, segmen JPEG (APPn, DQT, SOF), chunk PNG, tag PNG tEXt/iTXt | Parser sendiri + exifr + ExifTool (server) |
| Video | MP4, MOV, M4V, MKV/WebM, AVI, MPEG-TS, 3GP | Pohon box/EBML, tag kontainer, track, codec, hvcC/avcC, NAL, SEI, statistik frame, GOP, bitrate, edit list, chapter | Parser sendiri + MediaInfo (WASM) + ffprobe (server) |
| Audio | MP3, AAC/M4A, FLAC, OGG/Opus, WAV, AIFF | ID3v1/v2, Vorbis comment, APE, cover art, encoder, ReplayGain, chapter | music-metadata + parser sendiri |
| Dokumen PDF | PDF | Info dict, XMP, produser, versi, update inkremental (`%%EOF` ganda), file tertanam, JavaScript, anotasi, tanda tangan, font | pdf.js + parser sendiri |
| Dokumen Office | DOCX, XLSX, PPTX, ODT/ODS/ODP, EPUB | `docProps` core dan app, revisi, penulis perubahan, komentar, sheet tersembunyi, tautan eksternal, makro (`vbaProject.bin`), XML kustom | Parser ZIP + XML |
| Arsip | ZIP, TAR, GZ, 7z (daftar saja) | Daftar entri, timestamp, atribut, komentar, extra field | fflate/JSZip |
| Provenance | C2PA/Content Credentials pada JPEG, PNG, MP4, dll. | Manifest, penandatangan, assertion, status validasi | `@contentauth/c2pa-web` |
| Universal (fallback) | Format apa pun | Magic bytes, hash, entropi, strings, hex | Parser sendiri |

Catatan arsitektur format: dukungan ditentukan oleh **magic bytes**, bukan ekstensi. File yang ekstensinya tidak sesuai dengan isinya diberi peringatan.

## 6. Prinsip desain

1. **Parser deterministik, AI hanya penjelas.** Semua data berasal dari kode yang dapat diuji. LLM tidak pernah dipakai untuk mengurai file atau menebak nilai.
2. **Fakta dan tebakan dipisah.** Setiap temuan inferensial wajib membawa `confidence`.
3. **Privasi dulu.** Default tanpa unggah; jaringan dipakai hanya atas pilihan pengguna.
4. **Tidak ada yang disembunyikan.** Tag tak dikenal, field kosong yang bermakna (misalnya tanggal nol), dan byte tak terjelaskan tetap ditampilkan.
5. **Satu sumber kebenaran.** Semua tampilan membaca satu objek laporan JSON yang sama.
6. **Gagal dengan anggun.** Kegagalan satu analyzer tidak membatalkan laporan; ia menjadi `warning`.
7. **Setiap angka bisa ditelusuri** ke offset byte atau ke aturan yang menghasilkannya.

## 7. Arsitektur

### 7.1 Dua mode eksekusi

| Mode | Lokasi analisis | File keluar dari perangkat? | Kemampuan |
| --- | --- | --- | --- |
| **Privat** (default) | Browser (Web Worker + WASM) | Tidak | Parser sendiri, MediaInfo WASM, exifr, music-metadata, pdf.js, c2pa-web |
| **Mendalam** (opt-in) | Server Node.js | Ya, sementara, dihapus segera setelah selesai | Semua mode Privat + ExifTool lengkap (MakerNote, ribuan format) + ffprobe |

Mode Mendalam menampilkan peringatan jelas sebelum unggah. Hasil kedua mode digabung oleh orkestrator dengan skema laporan yang sama; bila kedua mesin memberi nilai berbeda untuk satu field, keduanya ditampilkan dan diberi tanda selisih.

### 7.2 Komponen

| Komponen | Tanggung jawab |
| --- | --- |
| UI (React) | Dropzone, tab laporan, visualisasi, ekspor |
| Orkestrator | Memilih analyzer sesuai tipe file, menjalankan paralel di Web Worker, menggabungkan hasil |
| Analyzer per lapisan | Fungsi murni yang mengembalikan JSON bagian laporan (lihat 7.3) |
| Mesin aturan | Cross-check dan inferensi dari JSON gabungan |
| Penghitung privasi | Skor risiko dan temuan berseverity dari hasil mesin aturan |
| Penyaji laporan | Tab interaktif, hex viewer, grafik, ekspor |
| Layanan server (opsional) | Endpoint analisis Mendalam, penyimpanan sementara, pembersihan, proksi Gemini |
| Modul AI Insight | Mengirim **hanya JSON metadata** (bukan isi file) ke Gemini dari server, untuk penjelasan |

### 7.3 Lapisan analisis

| Lapisan | Isi | Berlaku untuk |
| --- | --- | --- |
| L0 File | Nama, ukuran, MIME dari magic bytes, hash MD5/SHA-1/SHA-256 | Semua |
| L1 Tag | EXIF/XMP/IPTC/QuickTime/ID3/dll. | Semua |
| L2 Teknis | Codec, dimensi, bitrate, warna, durasi, sample rate | Media |
| L3 Struktur | Pohon box/segmen/chunk/objek/entri dengan offset dan ukuran | Semua |
| L4 Bitstream | hvcC/avcC, VPS/SPS/PPS, SEI, string encoder; tabel kuantisasi JPEG | Video, gambar |
| L5 Statistik | Frame, GOP, bitrate per detik, distribusi | Video, audio |
| L6 Cross-check | Konsistensi antar lapisan | Semua |
| L7 Inferensi | Korelasi, heuristik, label keyakinan | Semua |
| L8 Peta byte | Cakupan: byte terjelaskan vs tidak | Semua |

### 7.4 Alur pemrosesan

1. Terima file (referensi `File`, dibaca per potongan, tidak dimuat penuh ke memori).
2. Deteksi tipe dari magic bytes.
3. Jalankan L0, L1, L2, L3 paralel; L4 menunggu L3; L5 menunggu L2.
4. L6 dan L7 menunggu semua.
5. Hitung skor privasi dan peta byte.
6. Render laporan; AI Insight dijalankan terpisah bila pengguna memilihnya.

### 7.5 Penempatan di Google AI Studio Build

Berdasarkan dokumentasi resmi Build mode: aplikasi web dibuat sebagai lingkungan full-stack dengan frontend React dan runtime Node.js sisi server yang dapat memanggil paket npm; kunci API Gemini disimpan sebagai secret sisi server dan tidak dikirim ke kode klien; aplikasi bisa di-deploy ke Cloud Run, disinkronkan ke GitHub, atau diunduh sebagai ZIP. Konsekuensi untuk produk ini:

- Analisis Privat berjalan di klien (React + Web Worker), sehingga tidak bergantung pada server.
- Mode Mendalam dan AI Insight memakai server Node bawaan Build.
- Panggilan Gemini **harus** lewat server, bukan dari klien.
- Bila aplikasi diunduh sebagai ZIP, pengguna perlu mengatur variabel lingkungan `GEMINI_API_KEY` sendiri di hosting.
- ExifTool via `exiftool-vendored` membutuhkan Perl; pada image Docker Node yang `-slim`, Perl tidak tersedia (catatan dari repositori library). Bila lingkungan runtime tidak menyediakan Perl, Mode Mendalam harus **turun ke Mode Privat** dengan pesan jelas, bukan gagal.

## 9. Spesifikasi UX

### 9.1 Struktur layar

1. **Beranda:** dropzone besar, pemilih mode (Privat/Mendalam) dengan penjelasan satu kalimat, kebijakan privasi singkat.
2. **Laporan** (setelah analisis), berisi header dan tab:
   - **Ringkasan:** skor privasi, 3–5 temuan utama, status integritas (cross-check), label keyakinan, tombol AI Insight.
   - **Semua tag:** tabel dikelompokkan, pencarian, filter namespace.
   - **Struktur:** pohon dan peta cakupan byte; klik node membuka hex.
   - **Teknis:** panel per jenis file (video: track, bitstream, GOP, grafik; gambar: segmen JPEG dan ICC; dst.).
   - **Waktu dan lokasi:** timeline timestamp dan koordinat.
   - **Provenance:** C2PA, penanda AI, rantai pemrosesan.
   - **Integritas:** daftar cross-check dan inferensi dengan bukti.
   - **Hex dan strings.**
   - **JSON mentah** dan ekspor.
3. **Bandingkan:** dua kolom, diff berwarna.
4. **Batch:** tabel file dan skor.

### 9.2 Aturan penyajian

- Temuan inferensial selalu bertanda label keyakinan di samping teks.
- Nilai nol atau kosong yang bermakna ditulis jelas ("dikosongkan oleh platform"), bukan "N/A".
- Angka besar diformat dengan pemisah ribuan sesuai bahasa; satuan selalu ditulis.
- Peringatan privasi tidak menggunakan bahasa menakut-nakuti; ia menjelaskan apa, di mana, dan cara menanganinya.
- Setiap kartu temuan punya tautan "lihat bukti" ke field atau offset byte.

## 10. Mesin aturan

### 10.1 Cross-check (fakta)

| Aturan | Berlaku untuk | Kondisi lolos |
| --- | --- | --- |
| Jumlah sampel video | MP4/MOV | Entri `stsz` video = jumlah frame dari probe |
| Jumlah keyframe | MP4/MOV | Entri `stss` = jumlah frame key |
| Jumlah paket audio | MP4/MOV | Entri `stsz` audio = jumlah paket |
| Total ukuran | MP4/MOV, PNG, ZIP | Jumlah ukuran box/chunk tingkat atas = ukuran file |
| Durasi antar-sumber | Media | Durasi header, stream, dan format berselisih ≤ toleransi |
| Akhir file | JPEG, PNG, PDF | Marker akhir ada dan tidak ada data setelahnya (atau data tambahan ditandai) |
| Ekstensi vs isi | Semua | Magic bytes sesuai ekstensi |
| Hash di tag | Semua | Bila tag berisi hash, hasil uji region dilaporkan |
| Konsistensi tanggal | Semua | Tanggal pembuatan ≤ tanggal modifikasi; tidak di masa depan |
| Thumbnail vs gambar utama | JPEG | Rasio aspek thumbnail sesuai (indikasi pengeditan bila tidak) |

### 10.2 Inferensi (dengan keyakinan)

| Aturan | Kondisi | Kesimpulan | Keyakinan |
| --- | --- | --- | --- |
| Encoder dari bitstream | SEI user-data memuat nama encoder | Video di-encode oleh encoder itu | Kuat |
| Muxer dari kontainer | Tag `encoder` = `Lavf...` | Kontainer ditulis FFmpeg (versi dari nomor Lavf) | Kuat |
| Metadata dibersihkan | Semua tanggal nol, tanpa GPS/make/model | Jejak perangkat sudah dihapus | Kuat |
| Re-encode | Encoder bitstream dan muxer tidak sesuai perangkat rekam | Bukan hasil rekaman langsung | Kuat |
| Faststart | `moov` sebelum `mdat` | Siap streaming | Pasti |
| Waktu dari ID platform | 32 bit teratas ID video TikTok sebagai epoch | Perkiraan waktu posting | Heuristik |
| Perangkat dari EXIF | `Make`+`Model`+`Software` konsisten | Perangkat dan versi firmware | Kuat |
| Pengeditan gambar | `Software` memuat editor, atau XMP history ada | Gambar pernah diedit | Kuat |
| Revisi PDF | `%%EOF` ganda | Dokumen diubah setelah dibuat | Kuat |
| Penanda AI | `DigitalSourceType` bernilai algoritmik, atau teks parameter generator di PNG, atau manifest C2PA | Indikasi konten AI | Kuat (bila C2PA valid) / Heuristik (selain itu) |

Aturan disimpan sebagai daftar data (id, kondisi, kesimpulan, keyakinan, teks penjelasan dua bahasa) agar mudah ditambah tanpa mengubah parser.

### 10.3 Skor privasi

Skor dihitung dari temuan berseverity:

| Temuan | Severity |
| --- | --- |
| Koordinat GPS tepat | Tinggi |
| Nama pemilik/penulis/organisasi | Sedang–Tinggi (konteks) |
| Serial perangkat atau ID unik | Tinggi |
| Model perangkat dan software | Rendah |
| Tanggal dan jam pengambilan | Sedang |
| Thumbnail tertanam yang berbeda dari gambar (potensi kebocoran bagian yang dipotong) | Tinggi |
| Komentar, perubahan terlacak, atau sheet tersembunyi pada dokumen | Tinggi |
| ID platform yang menaut ke postingan publik | Sedang |
| Hanya data teknis (codec, dimensi) | Info |

Rumus skor dan bobot disimpan sebagai konfigurasi, dijelaskan di UI, dan bukan kotak hitam.

## 11. AI Insight (Gemini): kebutuhan dan batas

| Aspek | Ketentuan |
| --- | --- |
| Lokasi pemanggilan | Server saja; kunci API tidak pernah di klien |
| Data yang dikirim | Hanya JSON laporan yang sudah disaring (tanpa isi file, thumbnail, atau cover art); pengguna melihat apa yang akan dikirim sebelum setuju |
| Opt-in | Per laporan, bukan global |
| Fungsi | Ringkasan bahasa awam, penjelasan istilah, jawaban pertanyaan tentang laporan, saran langkah privasi |
| Larangan | Mengurai file; menebak nilai yang tidak ada di JSON; menyimpulkan identitas orang; menyajikan heuristik sebagai fakta |
| Pola jawaban | Wajib mengutip field atau temuan sumber; memakai label keyakinan yang sama dengan mesin aturan; menjawab "tidak ada di laporan" bila data tidak ada |
| Kegagalan | Bila Gemini gagal atau tidak tersedia, laporan tetap utuh; fitur AI menampilkan pesan dan bisa dicoba ulang |
| Pemilihan model | Gunakan model Gemini terbaru yang direkomendasikan AI Studio saat implementasi; jangan mengunci nama model di spesifikasi |

## 12. Kebutuhan non-fungsional

| Kategori | Kebutuhan |
| --- | --- |
| Kinerja | Pembacaan berbasis potongan (chunk); parsing berat di Web Worker; UI tidak membeku; target: ringkasan file ≤ 50 MB dalam ≤ 3 detik (target usulan) |
| Memori | Tidak memuat seluruh file ke memori untuk file besar; batas ukuran per mode dikonfigurasi |
| Privasi | Mode Privat tanpa permintaan jaringan yang membawa data file; Mode Mendalam: file sementara, dihapus segera setelah selesai, hasil berumur terbatas; tidak ada analitik yang mengirim nama file atau metadata |
| Keamanan | Semua nilai tag diperlakukan sebagai teks dan di-escape; CSP ketat; validasi ukuran box terhadap batas induk; batas waktu dan memori per analyzer; server berjalan non-root, tanpa akses keluar yang tak perlu; batas rate pada endpoint |
| Keandalan | Parser tidak boleh crash pada input rusak; setiap analyzer punya timeout; kegagalan menjadi `warning` |
| Aksesibilitas | WCAG 2.2 AA; seluruh fitur bisa dipakai dengan keyboard |
| Internasionalisasi | ID dan EN; format angka dan tanggal sesuai lokal |
| Observabilitas | Metrik durasi dan kegagalan per analyzer; log tanpa isi file dan tanpa nilai tag |
| Kepatuhan lisensi | Lihat bagian 16 |

## 15. Strategi pengujian

| Lapisan uji | Isi |
| --- | --- |
| Korpus | Berkas dari banyak asal: kamera ponsel, kamera aksi, hasil FFmpeg, unduhan platform, hasil editor, file rusak, terpotong, ekstensi salah |
| Golden files | JSON hasil terverifikasi manual per file korpus; dibandingkan tiap rilis |
| Uji silang | Bandingkan dengan ExifTool dan MediaInfo; selisih harus bisa dijelaskan |
| Fuzzing | Mutasi byte pada header box/segmen/objek; parser tidak boleh crash atau menggantung |
| Uji performa | File 1 MB, 50 MB, 500 MB; ukur waktu dan memori |
| Uji privasi | Pantau lalu lintas jaringan pada Mode Privat; harus tanpa data file |
| Uji aksesibilitas | Audit otomatis + uji keyboard dan pembaca layar |
| Uji AI | Set pertanyaan dengan jawaban yang harus mengutip field; uji halusinasi dengan pertanyaan tentang data yang tidak ada |

Fixture wajib: video contoh pada Lampiran A.

## 16. Risiko, etika, dan lisensi

| Risiko | Dampak | Mitigasi |
| --- | --- | --- |
| Penyalahgunaan untuk menelusuri orang | Pelanggaran privasi | Tidak ada fitur identifikasi orang; peringatan etika; temuan lokasi disertai penjelasan; label keyakinan agar tebakan tak dibaca sebagai fakta |
| Pengguna menganggap laporan sebagai bukti hukum | Kesimpulan salah | Pernyataan jelas di UI dan ekspor: metadata dapat diedit atau dihapus |
| Parser dieksploitasi file jahat | Kerusakan atau kebocoran | Validasi batas, timeout, isolasi worker, server non-root, tanpa akses keluar |
| Library WASM besar memperlambat muat | Pengalaman buruk | Muat malas (lazy) per jenis file |
| Perl/ExifTool tidak tersedia di runtime | Mode Mendalam gagal | Turun anggun ke Mode Privat dengan pesan |
| Halusinasi AI | Informasi menyesatkan | Batas AI di bagian 11; kewajiban mengutip field |
| Tile peta menyingkap koordinat | Kebocoran privasi | Peta dimuat atas klik, dengan penjelasan |
| Perubahan format platform (misalnya skema ID) | Heuristik usang | Heuristik berlabel dan mudah diperbarui; tidak pernah ditampilkan sebagai fakta |

Lisensi: periksa dan catat lisensi setiap dependensi (misalnya ExifTool, MediaInfoLib, c2pa-js) di berkas `THIRD_PARTY_LICENSES`; pastikan distribusi aplikasi memenuhi syaratnya. Dokumen ini bukan nasihat hukum.

## Lampiran B — Skema laporan (TypeScript)

```ts
type Confidence = 'pasti' | 'kuat' | 'heuristik';
type Severity = 'kritis' | 'tinggi' | 'sedang' | 'rendah' | 'info';

interface Report {
  meta: { schema: '1.0'; analyzedAt: string; mode: 'privat' | 'mendalam'; analyzers: Record<string, string> };
  file: {
    name: string; size: number;
    detectedType: string; extensionMatches: boolean;
    hashes: { md5: string; sha1: string; sha256: string };
  };
  tags: Array<{ ns: string; name: string; raw: unknown; decoded?: string; source: string; offset?: number }>;
  technical: { video?: VideoInfo; image?: ImageInfo; audio?: AudioInfo; document?: DocInfo };
  structure: Node[];
  bitstream?: {
    codec: 'hevc' | 'avc' | string;
    config: Record<string, unknown>;
    firstSampleNals: number[];
    seiUserData: Array<{ uuid: string; text: string }>;
  };
  stats?: {
    frames: number; keyframes: number; keyframeTimes: number[]; gopGaps: number[];
    kbpsPerSecond: { mean: number; median: number; min: number; max: number; stdev: number; series: number[] };
  };
  timeline: Array<{ label: string; value: string; utc?: string; tz?: string; anomaly?: string }>;
  location?: { lat: number; lon: number; alt?: number; source: string; accuracyNote?: string };
  provenance?: { c2pa?: { present: boolean; valid?: boolean; signer?: string; actions?: string[] }; aiMarkers: string[] };
  coverage: { explainedBytes: number; totalBytes: number; unexplained: Array<{ offset: number; size: number }> };
  checks: Array<{ id: string; name: string; status: 'lolos' | 'gagal' | 'tidak_berlaku'; detail?: string }>;
  findings: Array<{ id: string; text: string; confidence: Confidence; evidence: string[] }>;
  privacy: { score: number; items: Array<{ id: string; severity: Severity; text: string; advice: string }> };
  warnings: Array<{ analyzer: string; message: string }>;
}

interface Node {
  path: string; type: string; offset: number; size: number;
  error?: string; children?: Node[];
}
```
